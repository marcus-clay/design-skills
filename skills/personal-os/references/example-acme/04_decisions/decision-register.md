# Registre de décisions

Ajout seulement. On n'efface et on ne réécrit jamais une entrée. Une décision modifiée donne une nouvelle entrée qui renvoie à l'ancienne. Si la raison n'est pas connue, écrire « raison non documentée ».

## D-001 : un seul fichier de maquettes par produit

- **Date** : 2026-01-15
- **Décidée par** : Dana (VP Produit), avec Sam
- **Contexte** : deux versions concurrentes des écrans d'Acme Portal circulaient, et deux designers avaient travaillé sur des versions différentes d'un même écran.
- **Décision** : chaque produit a un seul fichier de maquettes, tenu par l'équipe design.
- **Raison** : éviter les divergences et faciliter la reprise d'un sujet par une autre personne.
- **Conséquences** : les anciennes versions sont archivées ; tout nouvel écran est créé dans le fichier du produit.
- **Remplace / remplacée par** : aucune
- **Source** : réunion du 15 janvier 2026 (notes de Sam)

## D-003 : checklist d'accueil v1 uniquement pour les nouveaux comptes

- **Date** : 2026-03-12
- **Décidée par** : Dana (VP Produit)
- **Contexte** : le support reçoit de nombreux tickets de personnes perdues à leur première connexion à Acme Portal. Trois formes sont envisagées (bandeau, fenêtre guidée, page dédiée).
- **Décision** : la première version de la checklist d'accueil ne s'affiche que pour les nouveaux comptes. Les comptes existants verront la checklist dans une version 2.
- **Raison** : migrer les données de profil des comptes existants demande une capacité technique que l'équipe n'a pas avant juillet (dit par Riley). Le bandeau est faisable avant l'été.
- **Conséquences** : la v1 sort sans migration ; les comptes existants ne voient pas la checklist avant la v2 ; la forme finale (bandeau ou autre) reste à trancher après les trois variantes de Morgan.
- **Remplace / remplacée par** : aucune
- **Source** : `archive/2026-03-12_sync-portal.txt`, passages de 03:30 à 05:00
